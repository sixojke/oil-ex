# analyze — балансер нефтяного мода

Утилита читает `common.json` (настройки мода) и `analyze.json` (параметры анализа), считает энергобаланс / потоки жидкостей / расход смазки и уплотнителей и печатает разноцветные таблицы в консоль.

## Запуск

```cmd
analyze.exe
```

Бинарь и оба JSON должны лежать в одной директории. Цвета — ANSI-escape (Windows Terminal, PowerShell 7, cmd на Windows 10+ — поддерживают из коробки).

## Файлы

- **`common.json`** — конфиг мода. Берётся как есть, ничего в нём не дублируем.
- **`analyze.json`** — параметры сборки и пороги покраски.
- **`analyze.exe`** — собранный бинарь (см. «Сборка»).

### `analyze.json`

```json
{
  "setup": {
    "max_oil_derricks": 2,
    "limit_refineries": 2,
    "limit_fuel_generators": 32,
    "turbine_seal_durability": 10000,
    "matter_eu_per_mb": 168350
  },
  "thresholds": {
    "oil_chunks_per_region": { "red_low": 0.4, "yellow_low": 0.8, "yellow_high": 2.0, "red_high": 4.0 },
    "lubricant_ratio":       { "red_low": 0.4, "yellow_low": 0.75, "yellow_high": 1.2, "red_high": 3.0 },
    "fluid_remainder":       { "red_low": 1000, "yellow_low": 5000, "yellow_high": 16000, "red_high": 32000 },
    "storage_ratio":         { "red_below": 1.0, "yellow_below": 2.0 },
    "seals_per_hour":        { "yellow_above": 30, "red_above": 120 },
    "limit_ratio":           { "yellow_factor": 1.5, "red_factor": 2.0 }
  }
}
```

**setup**

| поле | смысл |
|---|---|
| `max_oil_derricks` | макс. сценарных вышек, по которым строятся per-derrick таблицы |
| `limit_refineries` | сколько НПЗ выделено на фракции (3-й НПЗ автоматически считается под смазку) |
| `limit_fuel_generators` | плановое число генераторов |
| `turbine_seal_durability` | прочность одного уплотнителя |
| `matter_eu_per_mb` | EU за 1 mB UU-материи (`blockAdvancedMachine:4` ≈ 168350) |

**thresholds**

Четыре «фигуры» порогов — выбирается под конкретный смысл метрики:

- **`ZoneRange`** (4 точки): значения вне `[red_low, red_high]` → красный, дальше внутрь до `[yellow_low, yellow_high]` → жёлтый, в центре зелёный.
- **`ZoneBelow`** (больше = лучше): ниже `red_below` → красный, ниже `yellow_below` → жёлтый, иначе зелёный.
- **`ZoneAbove`** (меньше = лучше): выше `red_above` → красный, выше `yellow_above` → жёлтый, иначе зелёный.
- **`ZoneFactor`** (симметричное отклонение от лимита по множителю): `ratio = value / limit`, выход за `red_factor` или ниже `1/red_factor` → красный, аналогично для yellow.

Чтобы перебалансить — правь числа в `analyze.json` и запусти `analyze.exe` снова, перекомпилировать не надо.

## Что в выдаче

1. **Шапка** — энергоцены вышки/НПЗ/генераторов из `common.json`.
2. **Per-derrick таблицы** — для каждой комбинации (1..max вышек) × (gasoline / fuel_oil): загруженность НПЗ и генов на разных точках чанка, выход EU/t, профит и КПД базы и с уплотнителем.
3. **Чанки нефти на регион** — оценка плотности (128×128 блоков = 64 чанка).
4. **Проверка energy_storage** — что storage ≥ energy_cost за цикл (иначе машина встанет).
5. **Жидкости в минуту** — фракции / расход смазочным НПЗ / расход на 32 гена → остатки на крафты.
6. **Анализ выработки смазки** — расход сборщика, продукция 1 НПЗ, время налива бака.
7. **Расход турбинных уплотнителей** — шт/час на лимит генов.
8. **Производство UU-материи** — mB/час по топливу/режиму.

## Сборка

```cmd
go build -o analyze.exe analyze.go
```

Зависимость одна — `github.com/jedib0t/go-pretty/v6` (тянется через `go.mod`).
